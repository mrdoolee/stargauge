# 실기기 확인 가이드 (교사용)

갤럭시탭 S6 Lite(크롬)와 폰(아이폰 Safari 포함)에서 확인합니다.
결과는 아래 "결과:" 칸에 적어 주세요. 한 줄이면 충분합니다.

## 0. 내 컴퓨터에서 기기로 띄우기 (같은 Wi-Fi)

1. 컴퓨터와 기기를 **같은 Wi-Fi**에 연결합니다.
2. 프로젝트 폴더에서 터미널을 열고 실행합니다.

   ```
   npm run dev -- --host
   ```

3. 화면에 `Network: http://192.168.x.x:5173/` 같은 줄이 나옵니다. 그 주소를 기기 주소창에 입력합니다.
   - 안 보이면 터미널에 `ipconfig`를 입력합니다. "무선 LAN 어댑터 Wi-Fi"의 **IPv4 주소**가 컴퓨터 IP입니다.
   - 기기에서 `http://<컴퓨터 IP>:5173/?debug=1` 을 엽니다.
4. 처음 실행할 때 Windows 방화벽 창이 뜨면 **"액세스 허용"** 을 누릅니다. (개인 네트워크 체크)
5. 안 열리면: Wi-Fi가 같은지, 게스트 Wi-Fi가 아닌지, 방화벽 허용을 했는지 확인합니다.
6. 끝낼 때는 터미널에서 `Ctrl + C`.

`?debug=1` 을 붙이면 화면 왼쪽 아래에 FPS가 보입니다. 학생에게 줄 주소에는 붙이지 않습니다.

- `FPS` : 지금 속도
- `최저(10초)` : 최근 10초 중 가장 낮은 값
- `최저(전체)` : 미션을 시작한 뒤 가장 낮은 값

미션으로 바로 가기: `?debug=1&mission=m1` (또는 `m2`, `m3`, `m4`, `report`). 이전 미션 결과는 임시값으로 채워집니다.

## 1. 다섯 가지 확인

### 1) 멀티터치 경계

- [ ] 드래그 손가락을 먼저 떼고 발사 손가락만 남겨도 우주선이 튀지 않는다.
- [ ] 발사 버튼을 누른 순간 딱 1발만 나간다. (꾹 눌러도 연사되지 않음)

## 4. 수치 조정이 필요하면

파일은 모두 `src/config/balance.js` 입니다. 고친 뒤 새로고침하면 바로 적용됩니다.

| 이런 느낌이면 | 이 값을 바꾼다 |
|---|---|
| 우주선이 손가락에 가려 안 보인다 / 너무 멀다 | `SHIP_OFFSET_Y` (기본 140, 클수록 손가락에서 더 위) |
| 발사 버튼이 작다 / 크다 | `FIRE_BUTTON_DIAMETER` (140, 최소 120 권장), 위치는 `FIRE_BUTTON_MARGIN` (28) |
| 별이 너무 자주/드물게 나온다 | `SPAWN_INTERVAL_MS` (m1 1100, m2 2400, m3 1400, m4 800 밀리초. 클수록 느림) |
| 미션 1이 길다/짧다 | `MISSION_GOAL_COUNTS.m1` (8), `M1_PRACTICE_SEC` (30) |
| 미션 3 목표 수 | `MISSION_GOAL_COUNTS.m3a` (1) |
| 미션 2에서 필요한 색이 늦게 나온다 | `SPAWN_NEEDED_GUARANTEE` (3, 작을수록 빨리 나옴) |
| 미션 4 시간이 부족/남는다 | `M4_TIME_LIMIT_SEC` (210초) |
| 선체 온도가 너무 빨리 찬다 / 안 찬다 | `STAR_HEAT`, `FURNACE_HEAT`, `ASTEROID_HEAT` (15), `WRONG_SHOT_HEAT` (5) |
| 식는 속도 | `COOL_PER_SEC` (4, 클수록 빨리 식음) |
| 우주선이 느리게 따라온다 | `SHIP_FOLLOW_REMAIN_PER_SEC` (작을수록 빨리 따라옴) |

`STAR_HEAT` 기본값: 청색 30, 청백 25, 백색 20, 황백 16, 황색 12, 주황 8, 적색 5.
`FURNACE_HEAT` 기본값: 백색 25, 황색 15, 주황 9, 적색 5.

## 5. 성능 점검 (코드만 보고 한 정적 점검)

실기기가 없어서 측정은 못 했습니다. 코드에서 읽은 내용입니다. 실제 숫자는 위 FPS 테스트로 확인합니다.

**동시에 존재하는 물체 (미션 4, 가장 무거움)**
- 별 풀(미리 만들어 둔 별) 48개, 빔 16개, 소행성 12개를 시작할 때 한 번에 만들고 재사용합니다. 플레이 중 새로 만들거나 지우지 않습니다.
- 미션 4에서 실제로 쓰는 것: 성단 별 12개 + 흩어지는 청색 별(2.2초마다 1개, 몇 초 뒤 화면 밖으로 사라짐 → 동시에 2~4개) + 빔(연타해도 최대 16개). 즉 화면에 별 약 15개, 빔 약 5~16개입니다.
- 별마다 빛 번짐 이미지가 1개 더 붙습니다. 그래서 많아야 이미지 약 30~45장입니다.

**텍스처(그림) 크기**
- 별 128x128 7종, 빛 번짐 192x192 7종, 용광로 128x128 4종. 모두 합쳐도 약 2MB 미만입니다. 메모리 걱정은 없습니다.
- 빛 번짐은 겹쳐 그리는(ADD) 방식이라 큰 별 여러 개가 겹치면 그리기 부담(GPU)이 가장 커집니다. 느려진다면 이쪽이 1순위 의심입니다.

**프레임마다 하는 일**
- 불필요한 메모리 할당이 거의 없습니다. 풀 순회는 미리 만든 배열을 쓰고, HUD 이벤트는 값이 바뀔 때만 보냅니다(선체 온도는 1% 단위 변화 때만).
- 미션 4의 성단 별 12개는 매 프레임 위치만 갱신합니다.
- 그림 다시 그리기(Graphics clear/redraw)는 프레임마다 하지 않습니다. 버튼, 게이지, 토스트는 값이 바뀔 때만 다시 그립니다.
- 충돌 검사: 빔 16 x 별 48, 우주선 x 별 48 정도로 매 프레임 약 800쌍입니다. 가벼운 수준입니다.
- 앱 전환 뒤: 한 프레임 시간을 최대 100ms로 잘라서(`MAX_DT_MS`) 별이 한꺼번에 쏟아지거나 온도가 튀는 것을 막습니다.

**FPS가 30 미만이면 먼저 해 볼 것 (쉬운 순서)**
1. 빛 번짐 줄이기: `src/objects/starTextures.js` 의 `GLOW_TEX` 를 192에서 128로 낮추거나, 성단 별(12개)의 빛 번짐 투명도를 낮춥니다. 또는 `src/objects/Pools.js` 에서 `.setBlendMode(ADD)` 를 빼서 일반 합성으로 바꿉니다. (겹침 부담이 가장 크게 줄어듭니다.)
2. 풀 크기 줄이기: `src/config/balance.js` 의 `POOL_STARS` 48 → 24, `POOL_BEAMS` 16 → 10. 미션 4는 최대 약 15개, 다른 미션은 그보다 적게 쓰므로 여유가 있습니다. 풀이 모자라면 새 별이 안 나오니, 바꾼 뒤 미션 1~3도 한 번씩 해 봅니다.
