# 실기기 확인 가이드 (교사용)

갤럭시탭 S6 Lite(크롬)와 폰(아이폰 Safari 포함)에서 확인합니다.
결과는 아래 "결과:" 칸에 적어 주세요. 한 줄이면 충분합니다.

## 0. 내 컴퓨터에서 기기로 띄우기 (같은 Wi-Fi)

1. 컴퓨터와 기기를 **같은 Wi-Fi**에 연결합니다.
2. 프로젝트 폴더에서 터미널을 열고 실행합니다.

   ```
   npm run dev -- --host
   ```

3. 화면에 `Network: http://192.168.x.x:5173/` 같은 줄이 나옵니다. 그 주소를 기기 주소창에 입력합니다.
   - 안 보이면 터미널에 `ipconfig`를 입력합니다. "무선 LAN 어댑터 Wi-Fi"의 **IPv4 주소**가 컴퓨터 IP입니다.
   - 기기에서 `http://<컴퓨터 IP>:5173/?debug=1` 을 엽니다.
4. 처음 실행할 때 Windows 방화벽 창이 뜨면 **"액세스 허용"** 을 누릅니다. (개인 네트워크 체크)
5. 안 열리면: Wi-Fi가 같은지, 게스트 Wi-Fi가 아닌지, 방화벽 허용을 했는지 확인합니다.
6. 끝낼 때는 터미널에서 `Ctrl + C`.

`?debug=1` 을 붙이면 화면 아래 가운데(조이스틱과 발사 버튼 사이)에 FPS가 보입니다. 학생에게 줄 주소에는 붙이지 않습니다.

- `FPS` : 지금 속도
- `최저(10초)` : 최근 10초 중 가장 낮은 값
- `최저(전체)` : 미션을 시작한 뒤 가장 낮은 값
- 미션 시작 직후, 가로→세로로 돌린 직후, 다른 앱에서 돌아온 직후 0.5초는 기록하지 않습니다. (화면 준비 시간이라 실제 플레이 속도가 아님)

미션으로 바로 가기: `?debug=1&mission=m1` (또는 `m2`, `m3`, `m4`, `report`). 이전 미션 결과는 임시값으로 채워집니다.

## 1. 다섯 가지 확인

### 1) 조이스틱 + 발사 버튼 (멀티터치)
왼쪽 아래 반투명 원이 조이스틱(왼손 엄지), 오른쪽 아래 반투명 "발사"가 발사 버튼(오른손 엄지)입니다.
- [ ] 왼손 엄지로 조이스틱을 민 채, 오른손 엄지로 발사 버튼을 누른다. 우주선은 계속 움직이고 1발이 나간다.
- [ ] 조이스틱을 조금 밀면 느리게, 끝까지 밀면 빠르게 움직인다. 손을 떼면 우주선이 바로 멈추고, 가운데 손잡이도 제자리로 돌아온다.
- [ ] 조이스틱을 누른 채 엄지가 원 밖으로 나가도 계속 그 방향으로 움직인다. (멈추거나 튀지 않음)
- [ ] 엄지(조이스틱·발사 어느 쪽이든)가 게임 화면 밖 검은 띠까지 나가도 조이스틱이 끊기지 않는다.
- [ ] 과열로 미션이 다시 시작될 때 조이스틱 위 엄지를 떼지 않고 있으면 그대로 이어서 움직인다. (발사는 자동으로 되지 않음)
- [ ] 발사 버튼에서 시작한 손가락을 조이스틱 쪽으로 미끄러뜨려도 우주선이 움직이지 않는다.
- [ ] 조이스틱·발사 버튼이 아닌 곳(화면 가운데 등)을 만지거나 끌어도 우주선은 움직이지 않고, 발사도 되지 않는다.
- [ ] 발사 버튼을 누른 순간 딱 1발만 나간다. (꾹 눌러도 연사되지 않음) 누르는 동안 버튼이 조금 밝아진다.
- [ ] 우주선을 아래로 끝까지 내려도 조이스틱·발사 버튼 위에서 멈춘다. (엄지와 겹치지 않음)
- [ ] 별·쇳물·소행성이 조이스틱·발사 버튼 뒤로 지나가며, 반투명이라 그 뒤의 물체가 보인다.
- [ ] 조이스틱을 민 채 홈 버튼으로 나갔다 오거나 일시정지했다 이어 해도 우주선이 혼자 움직이지 않는다.

## 2. FPS 테스트 (가장 무거운 미션 4)

FPS는 **배포본과 같은 빌드**로 재는 것이 정확합니다. 개발 서버(`npm run dev`)는 코드를 압축하지 않고 실시간 변환을 해서 실제보다 느리게 나올 수 있습니다. 터미널에서 아래를 실행합니다.

```
npm run build && npm run preview -- --host
```

`Network: http://192.168.x.x:4173/` 같은 줄이 나옵니다. **포트가 4173**입니다(개발 서버는 5173). 개발 서버로 잰 값도 참고로 함께 적어 두면 좋습니다.

1. 기기에서 `http://<컴퓨터 IP>:4173/?debug=1&mission=m4` 를 연다.
2. 미션 4를 끝까지 한다. 중간에 쉬지 말고 움직이며 쏜다.
3. 끝나기 전에 `최저(전체)` 숫자를 읽어서 아래에 적는다.
4. 판단 기준: 최저가 **30 이상**이면 합격. 30 미만이면 아래 "FPS가 낮으면" 을 본다.

| 갤럭시탭 S6 Lite | 크롬 | preview | | | |

## 3-1. 난이도별 확인 (쉬움 / 어려움)

타이틀에서 난이도 버튼(쉬움·중간·어려움)을 고르고 "시작"을 누릅니다. 바뀌는 것은 떨어지는 속도, 나오는 개수, 부딪혔을 때 선체 온도뿐입니다. 정답 판정, 목표 개수, 미션 4 시간(210초)은 같습니다. 주소에 `?debug=1&mission=m1&difficulty=hard` 처럼 붙이면 바로 시작할 수 있습니다(교사용).

- [ ] 타이틀에서 고른 난이도가 눈에 띄게 표시된다(노란 버튼 + 체크). 결과 화면에 "난이도: …"가 나온다. "처음부터 다시" 후 타이틀에서 직전 선택이 그대로 선택돼 있다.
- [ ] 쉬움: 재시작(선체 온도 가득) 없이 끝까지 간다. 쉬움이 중간보다 확실히 느리고 적게 나온다.
- [ ] 어려움: 더 빠르고 많이 나온다. 끝까지 갈 수는 있지만 재시작이 몇 번 있을 수 있다.

## 4. 수치 조정이 필요하면

파일은 모두 `src/config/balance.js` 입니다. 고친 뒤 새로고침하면 바로 적용됩니다.

| 이런 느낌이면 | 이 값을 바꾼다 |
|---|---|
| 우주선이 너무 느리다 / 빠르다 | `SHIP_MAX_SPEED` (520, 조이스틱을 끝까지 밀었을 때 초당 픽셀) |
| 조이스틱이 작다 / 크다 | `JOYSTICK_DIAMETER` (200), 화면 가장자리와의 거리는 `JOYSTICK_MARGIN` (28) |
| 조이스틱을 살짝 건드려도 움직인다 / 조금 밀면 안 움직인다 | `JOYSTICK_DEAD_ZONE` (0.12, 원 반지름 대비 이 비율 안쪽은 "안 민 것") |
| 조이스틱을 누르려다 자꾸 빗나간다 | `JOYSTICK_HIT_SCALE` (1.3, 그려진 원보다 이 배수만큼 넓게 눌림) |
| 발사 버튼이 작다 / 크다 | `FIRE_BUTTON_DIAMETER` (150, 최소 120 권장), 위치는 `FIRE_BUTTON_MARGIN` (28) |
| 조이스틱·발사 버튼이 너무 진하다 / 흐리다 | `CONTROLS_ALPHA` (0.45, 평소), `CONTROLS_ACTIVE_ALPHA` (0.75, 누르고 있을 때) |
| 우주선이 조이스틱·발사 버튼에 너무 붙는다 / 너무 위에서 멈춘다 | `SHIP_CONTROL_CLEARANCE` (24, 우주선 아랫면과 조작 영역 사이 간격). 미션 시작 위치는 `SHIP_START_Y` (900) |
| 별(편대)이 너무 자주/드물게 나온다 | `FORMATION_GAP_MS` (m1 2100, m2 4000, m3 2400, m4 3000 밀리초. 편대와 편대 사이 쉬는 시간, 클수록 드묾). 난이도 배율(`spawnInterval`)이 곱해진다 |

## 5. 성능 점검 (코드만 보고 한 정적 점검)

실기기가 없어서 측정은 못 했습니다. 코드에서 읽은 내용입니다. 실제 숫자는 위 FPS 테스트로 확인합니다.

**동시에 존재하는 물체 (미션 4, 가장 무거움)**
- 별 풀(미리 만들어 둔 별) 48개, 빔 16개, 소행성 12개를 시작할 때 한 번에 만들고 재사용합니다. 플레이 중 새로 만들거나 지우지 않습니다.
- 미션 4에서 실제로 쓰는 것: 충전용 별(편대마다 3~5개, 동시에 2~3편대) + 보스 함선 1개 + 보스 탄(부채꼴 최대 3발씩) + 빔(연타해도 최대 16개). 즉 화면에 별 약 10~15개, 탄 몇 개, 빔 약 5~16개입니다. 미션 3은 별 약 10개 + 드론 최대 3기 + 드론 탄입니다.
- 별마다 빛 번짐 이미지가 1개 더 붙습니다. 그래서 많아야 이미지 약 30~45장입니다.

**텍스처(그림) 크기**
- 별 128x128 7종, 빛 번짐 192x192 7종, 용광로 128x128 4종. 모두 합쳐도 약 2MB 미만입니다. 메모리 걱정은 없습니다.
- 빛 번짐은 겹쳐 그리는(ADD) 방식이라 큰 별 여러 개가 겹치면 그리기 부담(GPU)이 가장 커집니다. 느려진다면 이쪽이 1순위 의심입니다.

**프레임마다 하는 일**
- 별·빔·소행성·효과(+1 글자, 고리)는 미리 만든 것을 재사용하므로 플레이 중 새 물체를 만들지 않습니다. 다만 작은 할당은 조금씩 생깁니다(명중할 때 판정용 작은 객체, 효과음마다 소리 노드 2~8개, 미션 4의 남은 별 목록 계산 등). 큰 문제가 될 양은 아니라고 보지만 측정한 것은 아니므로, 실제 영향은 위 FPS 테스트로 확인합니다.
- HUD 이벤트는 값이 바뀔 때만 보냅니다(선체 온도는 1% 단위 변화 때만).
- 미션 4의 보스는 매 프레임 좌우 위치만 갱신합니다.
- 그림 다시 그리기(Graphics clear/redraw)는 프레임마다 하지 않습니다. 버튼, 게이지, 토스트는 값이 바뀔 때만 다시 그립니다.
- 충돌 검사: 빔 16 x 별 48, 우주선 x 별 48 정도로 매 프레임 약 800쌍입니다. 가벼운 수준입니다.
- 앱 전환 뒤: 한 프레임 시간을 최대 100ms로 잘라서(`MAX_DT_MS`) 별이 한꺼번에 쏟아지거나 온도가 튀는 것을 막습니다.

**FPS가 30 미만이면 먼저 해 볼 것 (쉬운 순서)**
1. 빛 번짐 줄이기: `src/objects/starTextures.js` 의 `GLOW_TEX` 를 192에서 128로 낮추거나, 별의 빛 번짐 투명도를 낮춥니다. 또는 `src/objects/Pools.js` 에서 `.setBlendMode(ADD)` 를 빼서 일반 합성으로 바꿉니다. (겹침 부담이 가장 크게 줄어듭니다.)
2. 풀 크기 줄이기: `src/config/balance.js` 의 `POOL_STARS` 48 → 24, `POOL_BEAMS` 16 → 10. 미션 4는 최대 약 15개, 다른 미션은 그보다 적게 쓰므로 여유가 있습니다. 풀이 모자라면 새 별이 안 나오니, 바꾼 뒤 미션 1~3도 한 번씩 해 봅니다.
