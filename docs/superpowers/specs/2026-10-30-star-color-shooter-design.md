# 별빛 탐사선 스타게이지호 — 설계 문서

작성일: 2026-10-30
상태: 초안 (교사 승인 대기)

## 1. 의도와 배경

중학교 2학년 과학 「VIII. 별과 우주 › 1. 별 › 03 색으로 비교하는 별의 표면 온도」 차시에서 학생이 **별의 색과 표면 온도의 관계**를 몸으로 익히도록 하는 터치 기반 웹 슈팅 게임.

두 자료를 엮는다.

- **교과서** (`reference/8-1-3.pdf`): 용광로 쇳물 색 변화 비유, 별의 색 7단계(청색 › 청백색 › 백색 › 황백색 › 황색 › 주황색 › 적색, 왼쪽일수록 표면 온도 높음), 실제 별 예시(시리우스=백색, 리겔=청백색, 베텔게우스=적색, 태양=황색), "표면 온도는 크기·밝기가 아니라 색으로 안다", 스스로 확인하기 2문항.
- **NOIRLab 「Jewels of the Night」** (eduprog031): 보석상자 성단(NGC 4755) 컬러 사진에서 별의 색·밝기를 StarGauge로 측정하고 색-밝기 그림을 그리는 활동. 게임에서는 '스타게이지'라는 7칸 색 게이지와 마지막 보스 스테이지(보석상자 성단)로 가져온다.

핵심 학습 포인트는 단 하나: **청색일수록 표면 온도가 높고 적색일수록 낮다. 밝기·크기는 온도와 무관하다.** 많은 학생이 생활 경험(수도꼭지, 불꽃) 때문에 "빨강 = 뜨거움"이라고 생각하므로, 게임은 이 직관을 깨는 데 초점을 둔다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 학생 1명이 혼자 약 15분 안에 처음부터 끝까지 플레이할 수 있다.
- 플레이를 마친 학생은 7가지 색을 온도 순으로 배열하고, "밝은(큰) 별 ≠ 뜨거운 별"을 이유와 함께 고를 수 있다.
- 태블릿·스마트폰 브라우저에서 설치 없이 링크로 바로 실행된다.

**비목표 (이번 범위 아님)**
- 교사용 결과 수집, 로그인, 서버 저장. 결과는 학생 화면에서 끝난다.
- 색각이상 보조 기능 (교사 결정으로 제외).
- 키보드·마우스·게임패드 최적화 (동작은 해도 되지만 설계 기준은 터치). 키 재설정 기능 없음.
- 켈빈(K) 같은 온도 수치. 교과서처럼 '높다/낮다' 상대 비교만 쓴다.
- H-R도, 성단 나이 결정 등 중2 범위를 넘는 내용 (결과 화면 한 줄 언급만 허용).

**안티목표 (이러면 실패)**
- 별의 크기나 밝기가 온도 판정·선체 온도 상승에 영향을 주는 것. 학습 내용과 정면으로 어긋난다.
- 별의 색이 교과서 7단계와 다르게 보이거나 단계 간 구분이 모호한 것.
- **실제 별·성단을 다루는 장면에서 사실과 다른 내용을 보여 주는 것** (예: 실제보다 뜨거운 별이 있는데 다른 별을 '가장 뜨겁다'고 정답 처리).
- 조작이 어려워서 '몰라서 틀린 것'과 '손이 꼬여 틀린 것'이 구분되지 않는 것.
- 15분을 크게 넘기는 것.
- 별을 '파괴'하는 연출. 학생은 별에 **온도 탐지 빔**을 쏴서 '표시(측정)'한다.

## 3. 대상·환경

- 대상: 중학교 2학년.
- 기기: **학교 보급 갤럭시탭 S6 Lite**(10.4인치, 1200×2000, 중급 사양 안드로이드 크롬)와 **학생 개인 스마트폰**(안드로이드 크롬, 아이폰 사파리 혼재). **세로 화면** 기준. 1인 1기기.
  - 성능 기준선은 갤럭시탭 S6 Lite: 이 기기에서 끊김 없이(목표 60fps, 최소 30fps 이상 유지) 돌아야 한다.
  - 화면 비율 차이가 크다: 탭 S6 Lite 세로 약 3:5, 최신 폰 세로 약 9:19.5. 두 비율 모두에서 HUD·발사 버튼이 잘리지 않고 플레이 영역이 공정해야 한다 (스케일 방식은 빌더 결정, 두 비율 모두 실제 확인 필수).
  - 아이폰 사파리에서 길게 누르기·더블탭 확대·스크롤 튕김 같은 브라우저 기본 터치 동작이 게임을 방해하지 않게 막는다.
- 수업 내 위치: 45분 차시 중 약 15분. 나머지는 교사 정리.
- 언어: 한국어 UI. 교과서 용어(표면 온도, 청색, 청백색 …)를 그대로 쓴다.

## 4. 조작 (확정 — 2026-10-31 교사 결정으로 개정)

> 개정 이유: 화면 드래그 방식은 손이 화면 전체를 오가야 해서 오른쪽 발사 버튼을 동시에 누를 수 없었다 (교사 실기기 확인). 아래 C안(반투명 조작, 조작판 없음)으로 바꾼다.

- **이동 — 가상 조이스틱**: 화면 **왼쪽 아래 고정 위치**에 반투명 조이스틱. 왼손 엄지로 민 방향으로 우주선이 움직이고, **많이 밀수록 빠르며**, 손을 떼면 멈춘다. 조이스틱 밖을 만져도 우주선은 움직이지 않는다 (화면 드래그 이동은 없앤다).
- **발사**: 화면 **오른쪽 아래** 반투명 **발사 버튼**을 누를 때만 발사. 자동 연사 없음. 학생이 "이 별을 쏘겠다"고 의도해야 한다는 점이 핵심.
  - 버튼 한 번 누름 = 한 발 (누른 순간 기준, `input-systems`의 edge 입력). 누르고 있어도 연사하지 않는다.
- 조이스틱과 발사 버튼은 동시에 쓸 수 있어야 한다 (멀티터치). 각 손가락은 처음 누른 컨트롤에만 속한다.
- **조작판 없음**: 조이스틱·버튼은 반투명으로 게임 화면 위에 떠 있고, 별·쇳물·소행성은 그 뒤로 지나간다.
- **우주선 이동 범위**: 아래로는 조이스틱·발사 버튼 높이 **바로 위 선까지만** 내려온다 (조작 영역에서는 부딪힘이 생기지 않는다). 좌우는 화면 끝까지.
- 크기·투명도 시작값(빌더 결정, 실기기에서 조정): 조이스틱 지름 약 200px, 발사 버튼 약 150px (게임 해상도 720 기준).
- 화면은 **세로 스크롤 슈팅** 형식: 별·소행성·쇳물 등이 위에서 아래로 흘러온다.

## 4-1. 난이도 (2026-10-31 교사 결정으로 추가)

> 2026-11-03 개정: `docs/superpowers/specs/2026-11-03-patterns-art-briefing-design.md` 참고

- 타이틀에서 **쉬움 / 중간 / 어려움** 중 하나를 고르고 시작한다. "처음부터 다시"를 하면 다시 고를 수 있다. 결과 화면에 고른 난이도를 표시한다.
- **바뀌는 것은 게임 조작 난이도뿐**: ① 별·쇳물·소행성이 떨어지는 **속도**, ② 떨어지는 별의 **수**(등장 간격), ③ 부딪혔을 때 **선체 온도가 오르는 양**.
- **바뀌지 않는 것**: 배우는 내용 전부(7색, 정답 판정, 실제 별 데이터, 미션 지시, 퀴즈), 미션 4 **제한 시간**, 선체 온도 상승의 **색 순서**(청색 최대 → 적색 최소, 크기·밝기 무관).
- **중간 = 현재 수치.** 쉬움은 더 느리고·적게·덜 뜨겁게, 어려움은 더 빠르고·많이·더 뜨겁게.
- **목표**: 쉬움·중간은 학생 누구나 끝까지 마칠 수 있어야 한다. 어려움은 마칠 수는 있되 다소 어렵다 (재시작이 몇 번 나올 수 있는 수준).

## 5. 핵심 규칙

### 5.1 별의 색 7단계

> 2026-11-03 개정: `docs/superpowers/specs/2026-11-03-patterns-art-briefing-design.md` 참고
- 청색, 청백색, 백색, 황백색, 황색, 주황색, 적색. 이 7개가 게임 내 유일한 색 분류.
- 별은 **코드로 그린다** (고정 팔레트). 이미지 생성 결과로 색이 흔들리면 안 되기 때문. (설계자 판단)
- 각 별은 색과 별개로 **크기·밝기(빛 번짐)** 값을 가진다. 이 값은 시각적 함정용일 뿐 판정에는 쓰지 않는다.

### 5.2 쏘기 (표시)
- 미션 조건에 맞는 별을 맞히면: 정답 효과 + 스타게이지 해당 칸 채움 + 점수.
- 조건에 안 맞는 별을 맞히면: 짧은 피드백(1줄, 색 사다리 그림과 함께) + 선체 온도 소폭 상승. 게임을 멈추지 않는 짧은 토스트 형태.

### 5.3 피하기 — 선체 온도
- 별에 부딪히면 우주선 **선체 온도**가 오른다. 상승량은 **색으로만** 결정: 청색 최대 → 적색 최소로 단조 감소. 크기·밝기 무관.
- 쇳물 덩어리도 같은 규칙(흰색이 가장 크게, 붉은색이 가장 작게).
- 소행성은 색과 무관한 일정량.
- 선체 온도는 시간이 지나면 천천히 식는다.
- 선체 온도가 가득 차면 **그 미션만** 처음부터 다시 (게임 전체 재시작 아님).
- 구체적인 수치는 빌더가 플레이테스트로 정한다.

### 5.4 스타게이지 HUD
- 화면 위쪽에 7칸 게이지. 왼쪽 '높다' ↔ 오른쪽 '낮다', 아래에 '표면 온도' 라벨.
- 교과서 그림 8-5의 순서와 같아야 한다.
- 태양(황색) 기준 아이콘을 HUD에 상시 표시 (미션 2부터).
- 선체 온도 바, 남은 목표 수, 일시정지·음소거 버튼.

## 6. 미션 흐름 (약 15분)

> 2026-11-03 개정: `docs/superpowers/specs/2026-11-03-patterns-art-briefing-design.md` 참고

구성 원칙은 `level-design`의 "가르치고 → 연습시키고 → 시험한다(톱니형 난이도)"를 따른다. 새 규칙은 안전한 상황에서 먼저 보여 주고, 압박은 그다음에 준다. 미션 사이에는 짧은 쉼(정리 카드)을 둔다.

### 미션 1. 용광로 탈출 — 튜토리얼 + 도입 (약 2분)
- 교과서 도입(용광로 쇳물) 연결.
- 쇳물 덩어리가 위에서 떨어지며 **떨어지는 동안 식어서** 흰색 → 노란색 → 붉은색으로 변한다.
- 처음 30초는 장애물 없이 조이스틱 이동·발사만 연습 → 이후 미션: "가장 뜨거운 쇳물을 쏴라" (흰색에 가까운 덩어리가 정답).
- 선체 온도 규칙도 여기서 처음 체험 (흰 덩어리에 부딪히면 많이, 붉은 덩어리는 조금).
- 끝날 때 정리 카드: "뜨거울수록 흰색, 식을수록 붉은색. 별도 그래요!"

### 미션 2. 스타게이지 보정 — 7가지 색과 온도 순서 (약 4분)
- 7가지 색의 별이 무작위 크기·밝기로 흘러온다. HUD에 태양 기준.
- 이 미션의 별은 이름 없는 가상의 별이다 (실제 별 아님).
- 2-a: "태양보다 **뜨거운** 별만 쏘고 나머지는 피하라" → 청색·청백색·백색·황백색 칸이 채워진다.
- 2-b: "태양보다 **차가운** 별만 쏘고 나머지는 피하라" → 주황색·적색 칸이 채워진다. 황색 칸은 태양으로 미리 채워져 있다.
- 7칸이 모두 채워지면 클리어. 클리어 화면에 완성된 게이지 = 교과서 그림 8-5.

### 미션 3. 밝기의 함정 — 실제 별 (약 3분)
- **판정 대상은 교과서에 나온 세 별만**: 리겔(청백색), 시리우스(백색), 베텔게우스(적색). 셋 다 실제 별 이름 라벨 표시.
- 실제 표면 온도 순서는 리겔 > 시리우스 > 베텔게우스로, 교과서 색과 일치한다.
- 베텔게우스는 **가장 크게**(초거성), 시리우스는 **빛 번짐이 가장 밝게**(밤하늘에서 가장 밝은 별) 그린다. 리겔은 그보다 작게.
- 오리온자리의 다른 별(허리띠 세 별, 벨라트릭스 등)은 실제로 리겔보다 뜨거운 청색 별이므로 **판정 대상에서 빼고**, 쏠 수 없는 흐린 배경 별로만 둔다. (설계자 판단 — 사실 오류 방지)
- 함정용 '크고 밝은 적색 별'은 별자리 밖을 흐르는 **이름 없는 별**로만 넣는다. 실제 별자리 안에 가짜 별을 넣지 않는다.
- 3-a: "세 별 중 가장 뜨거운 별 하나만 쏴라" → 정답 리겔.
- 3-b: "표면 온도가 높은 순서대로 쏴라" → 리겔 → 시리우스 → 베텔게우스.
- 베텔게우스·시리우스를 '가장 뜨거운 별'로 쏘면 피드백: "베텔게우스는 아주 크지만 **적색** → 표면 온도가 낮아요. / 시리우스는 가장 밝지만 **백색** → 리겔보다 낮아요. 온도는 **색**으로 비교해요."
- 클리어하면 오리온자리·큰개자리 **완성 그림**을 보여 준다. 그림 속 모든 별은 **실제 색**으로 칠한다 (허리띠 별도 청색). 교과서 탐구 '별자리 별의 색 표시하기'를 대신하고, 심미적 가치를 느끼게 하는 장면.

### 미션 4. 보스 — 보석상자 성단 (약 4분)
- NOIRLab 활동 연결. 실제 보석상자 성단은 대부분 청색·청백색의 밝은 별이고, 그 사이에 **눈에 띄게 붉은 적색 초거성**이 있다.
- 게임 속 성단은 실제 성단을 **단순화한 그림**이다 (별 10~12개). 화면에 "실제 성단을 바탕으로 단순화했어요"를 작게 표기.
- 적색 초거성이 보스: **아주 커서** 위협적으로 보이지만 부딪혀도 선체 온도는 조금만 오른다. 반대로 작은 청색 별들은 흩어지며 날아와 선체 온도를 크게 올린다 → "작고 파란 별이 더 뜨겁다"를 체감.
- 보스는 별을 공격하지 않는다. 보스전의 압박은 '흩어지는 청색 별 피하기 + 시간 제한 안에 모두 표시하기'에서 나온다.
- 미션: 성단의 별을 모두 표시하라. 맞힌 별은 색에 따라 스타게이지에 쌓인다.
- 마지막 질문(화면 선택지, 사실과 맞는 것만 묻는다):
  - "이 성단에 가장 많은 별의 색은?" → 청색·청백색
  - "붉은 초거성은 크기가 가장 크다. 그럼 표면 온도도 가장 높을까?" → 아니다, 적색이므로 낮다
- 결과 화면: 게임 속 성단 별의 **색별 개수 막대그래프** + 한 줄 심화 ("청색 별이 많은 성단은 비교적 젊은 성단이에요").
- NOIRLab 이미지·자료를 화면에 쓰면 NOIRLab 크레디트를 보이는 곳에 반드시 표기 (사용 조건).

### 미션 5. 귀환 보고서 — 확인 퀴즈 (약 1~2분)
액션 없이 선택형 3문항.
1. 개념 확인: "별은 표면 온도가 (높을수록 / 낮을수록) 청색을 띤다."
2. 사고력: 유리 공예 장면에서 (가) 노란빛 부분과 (나) 붉은빛 부분 중 온도가 높은 곳과 이유 고르기. 그림은 교과서 이미지를 복제하지 않고 새로 만든다.
3. 설명: "베텔게우스는 아주 큰 별인데 왜 가장 뜨거운 별이 아닐까?" 이유 고르기 (성취기준 '설명할 수 있다' 보완).

### 최종 결과 화면
- 미션별 별점/점수, 퀴즈 결과, 완성 스타게이지, 오리온자리 그림.
- 학생 화면에서 끝. 저장·전송 없음. "처음부터 다시" 버튼.

## 7. 아트·사운드

> 2026-11-03 개정: `docs/superpowers/specs/2026-11-03-patterns-art-briefing-design.md` 참고

`create-game-assets` 스킬의 흐름을 따른다.

1. **기술 틀 고정**: Phaser 2D, 세로 화면, 기준 해상도(빌더 결정), 투명 PNG, 대상 기기.
2. **아트 디렉션 브리프** 작성 (스킬의 `assets/art-direction-brief.md` 양식): 형태 언어, 팔레트 역할, 외곽선, 디테일 밀도. 화풍은 중학생 친화적인 밝은 2D 카툰/네온 우주풍 (설계자 판단, 변경 가능).
3. **에셋 목록(manifest)** 작성 (스킬의 `assets/asset-manifest.json` 양식): 우주선, 소행성, 쇳물/용광로 배경, 우주 배경, 성단 배경, 타이틀, 유리 공예 일러스트, 발사 버튼·UI 장식.
4. **대표 에셋 1개(우주선) 먼저 승인** → 그것을 기준으로 나머지를 같은 계열로 생성.
5. **정규화·검수**: 크기·투명도·잘림을 스킬의 `asset_report.py`, `build_preview_sheet.py`로 확인하고, 실제 게임 화면에서 확인.
6. **출처 기록**: 생성 도구·프롬프트·날짜, NOIRLab 자료 사용 조건을 manifest 옆에 기록.

- 이미지 생성은 **OpenAI 이미지 API** 사용 (교사 결정). 키는 프로젝트 루트 `.env`의 `OPENAI_API_KEY`, 모델은 `OPENAI_IMAGE_MODEL`(= `gpt-image-2.5-sunburst`, 교사 지정). 생성 스크립트는 모델명을 코드에 박지 말고 이 변수에서 읽는다. (2026-10-30 키 인증·모델 존재 확인 완료)
- **개발 시점에만** 스크립트로 이미지를 생성해 정적 파일로 저장한다. 게임 코드·배포물에 API 키가 들어가면 안 된다 (학생 브라우저에 키 노출 금지).
- 키·모델은 준비됐지만, 회색 도형 프로토타입(9절 1단계)이 통과하기 전에는 이미지를 생성하지 않는다.
- 코드로 그리는 대상: 모든 별(색 정확성), 빔, HUD 게이지, 텍스트. UI 텍스트는 이미지에 굽지 않는다.
- 사운드 (`audio-design`): Master ← SFX / UI / Music 버스 구조, 효과음 위주, 기본 볼륨 낮게, 음소거 버튼 필수 (교실 환경). 반복 효과음은 피치를 살짝 바꿔 단조로움을 줄인다. 배경음은 선택.

## 8. 기술 결정과 적용 스킬

- 웹 브라우저 게임. 엔진은 **Phaser 4.2** (설계자 판단 — 교사가 지정한 gamedev-skills 저장소에서 웹 2D에 맞는 스킬이 Phaser용).
- 빌드 결과는 정적 파일(HTML/JS/이미지). 서버 불필요.
- **배포 (교사 결정)**: GitHub 저장소를 새로 만들고 Vercel에 연결해 배포한다. 학생은 Vercel 주소(링크·QR)로 접속.
  - `.env`(API 키)는 절대 커밋하지 않는다 (`.gitignore`에 이미 포함). 이미지 생성 스크립트와 생성된 이미지 파일만 커밋.
  - Vercel에는 환경변수를 넣지 않는다 (게임 실행에 키가 필요 없음).
  - 저장소 이름·공개 여부는 배포 단계에서 교사에게 확인.
- 교사가 지정한 스킬 저장소 <https://github.com/gamedev-skills/awesome-gamedev-agent-skills> 를 프로젝트 `.claude/skills/`에 설치했다 (77개 + `router`, `skills-lock.json`으로 버전 고정). 개발 중에는 `router`가 작업에 맞는 스킬을 고르고, 해당 `SKILL.md`를 읽은 뒤 작업한다.

| 영역 | 스킬 | 이 게임에서 지킬 것 |
|---|---|---|
| 엔진 뼈대 | `phaser-core` | 미션마다 Scene 1개, HUD는 별도 Scene을 한 번만 `launch`하고 `bringToTop`. 미션 재시작 시 상태는 생성자가 아니라 `init()`에서 초기화. `scale: FIT` + 가운데 정렬. 미션 간 데이터는 `registry`로. |
| 충돌·이동 | `phaser-arcade-physics` | 별·소행성·빔은 Arcade 바디 + 그룹. 충돌은 `overlap`으로 판정(밀어내지 않음). collider/overlap은 `create`에서 한 번만 등록. 빠른 빔이 별을 뚫고 지나가지 않게 속도·바디 크기 확인. |
| 입력 | `input-systems` | 게임 로직은 '이동'·'발사' **행동** 단위로 읽는다. 이동은 지속(held), 발사는 누른 순간(edge). 짧은 입력 버퍼로 살짝 이른 발사도 인정. |
| HUD·메뉴 | `game-ui-ux` | 절대 좌표 대신 화면 모서리 기준 배치, 노치·둥근 모서리 **안전 영역** 안쪽에 HUD. 휴대폰에서도 읽히는 글자 크기. HUD는 이벤트로 갱신(매 프레임 읽기 X). 화면 전환은 스택(일시정지 위에 덮기 → 닫으면 복귀). |
| 손맛 | `game-feel` | 정답 표시 / 오답 / 피격을 작은·중간·큰 3단계 연출로 나눔. 화면 흔들림·정지 효과는 피격 같은 큰 사건에만, 짧게. 연출 중에도 입력은 막지 않음. |
| 미션 흐름 | `level-design` | 가르치고 → 연습 → 시험, 톱니형 난이도, 미션 사이 쉼. 회색 도형 단계에서 흐름부터 검증. |
| 에셋 | `create-game-assets` | 7절 참조. |
| 사운드 | `audio-design` | 7절 참조. |
| 성능 | `performance-optimization` | 별·빔·소행성은 **오브젝트 풀**로 재사용(매번 생성·삭제 금지). 실제 학교 기기에서 프레임 시간을 재고 숫자로 보고. |
| 진행 방식 | `prototype-fast` | 9절 1단계. |

- 세로 화면 고정, 다양한 해상도 대응(레터박스 또는 FIT 스케일).
- 이 저장소에는 세로 슈팅 장르 전용 스킬이 없다. 장르 구조는 위 스킬들을 조합해 직접 짠다.

## 9. 개발 순서 (권장)

1. **회색 도형 프로토타입** (`prototype-fast`): 답할 질문은 하나 — "폰·태블릿에서 드래그 이동 + 발사 버튼 + 선체 온도 피하기가 중학생 손에 맞는가?" 원·사각형만 쓰고 미션 2 한 장면만 만든다. Vercel 미리보기 주소로 올려 교사가 **갤럭시탭 S6 Lite와 폰에서** 직접 해 보고 계속/수정 결정. 이 코드는 버리고 본 개발은 다시 짠다.
2. **전체 미션 흐름을 회색 도형으로** 완성하고 15분 안에 끝나는지 확인.
3. **아트 디렉션 확정 → 에셋 생성·교체** (`create-game-assets`).
4. **손맛·사운드** 추가 (`game-feel`, `audio-design`).
5. **갤럭시탭 S6 Lite 성능 측정·폰 비율 확인 → Vercel 정식 배포**.

## 11. 설계자 판단으로 정한 것 (교사 확인 권장)

- 별은 코드로 그리고, AI 이미지는 별 외 요소에만 사용.
- 별을 '파괴'하지 않고 '온도 탐지 빔으로 표시'하는 설정.
- 발사 버튼 한 번 = 한 발 (누르고 있어도 연사 없음).
- 선체 온도 가득 → 해당 미션만 재시작.
- 미션 3 판정은 교과서 세 별만, 나머지 오리온 별은 배경. 함정 별은 이름 없는 별로.
- 미션 4 성단은 단순화한 그림이며, 질문은 사실과 맞는 것만.
- 미션 3 클리어 시 별자리 완성 그림 제공, 귀환 보고서 3번 문항 추가.
- Phaser 4.2 사용, 회색 도형 프로토타입부터 시작.
- 화풍: 밝은 2D 카툰/네온 우주풍.
