# 플레이 중 안내 문구·단계 전환·드론 피해 누적·보스 체력 게이지 — 설계

상태: 교사 승인 ("이대로 개선해보자", 보스 피해 누적 "응 알아서 조정해줘")

## 1. 의도

교사가 플레이해 보고 말했다.
- "게임 중간에 뜨는 메시지 창이 화면을 너무 가려서 플레이가 불편해." "문구 창이 화면 가운데 뜨니까 날아오는 별이나 운석이 안 보여."
- "2라운드에서 태양보다 뜨거운 별에서 차가운 별로 바뀔 때 위에 텍스트만 바뀌니까 바뀌는지 모르겠음. 유저가 인식할 수 있는 과정이 필요함."
- "3라운드에 드론이 한 번에 쓰러지는 게 아니라, 충전된 색의 온도에 따라서 데미지가 누적되는 방식으로 개선해줘." 방어막보다 차가운 색으로 충전한 빔은 "튕기는 게 더 나을 듯".
- "4라운드에서는 보스의 체력 게이지 같은 게 보이면 좋겠다."
- "나오는 텍스트들 확인해서 줄바뀜 어색한 부분 찾아서 줄바뀜 처리 진행해."

교사는 아래 2·3절의 방향("플레이 중엔 화면에 아무것도 안 띄우고, 멈추는 순간에만 가운데 큰 안내")을 승인했다("이대로 개선해보자").

## 2. 목표 / 비목표 / 안티목표

**목표**
- 플레이 중에는 별·소행성·드론·탄이 지나가는 화면(HUD 띠 아래 ~ 조작 영역 위)을 어떤 안내 창도 가리지 않는다.
- 2라운드 1단계 → 2단계 전환을 학생이 확실히 알아챈다.
- 3라운드에서 "뜨거운 별일수록 에너지가 크다"를 피해량으로 체감한다. 방어막만 겨우 뚫는 색보다 더 뜨거운 별을 찾을 이유가 생긴다.
- 4라운드에서 보스가 얼마나 남았는지 한눈에 보인다.
- 게임의 모든 한국어 문구가 어색한 자리에서 줄이 바뀌지 않는다.

**비목표**
- 새 미션, 퀴즈(귀환 보고서) 문항, 브리핑 화면 구조, 난이도 체계(긴장도·속도 띠·반응 시간 하한), 별점 기준(2026-11-06 임시값 3/8) 변경.
- 문구 내용(뜻) 바꾸기. 줄바꿈 정리는 줄 나누는 자리만 바꾼다. 줄여야만 들어가는 문구는 예외로 하고, 바꾼 목록을 교사에게 보고한다.

**안티목표 (이러면 실패)**
- 플레이 중 안내가 날아오는 물체를 가린다.
- 단계 전환 안내가 떠 있는 동안 별·탄이 움직여서 학생이 맞거나 놓친다(전환 중에는 위험이 없어야 한다).
- 체력 막대·게이지 색이 별 온도 팔레트 색처럼 보여서 "적색 = 체력 낮음" 같은 잘못된 연상을 준다. 체력 표시는 팔레트가 아닌 중립색(흰색/회색)으로 채운다. 방어막·장갑 색 표시는 지금처럼 정확한 팔레트 hex.
- 피해량이 별의 크기·밝기에 따라 달라진다(색 7단계로만).
- 방어막보다 차가운 색의 빔이 조금이라도 피해를 준다(교사 결정: 튕긴다).
- 쉬움에서 끝까지 못 간다. 쉬움 전체 예상 시간 > 15분.

## 3. 플레이 중 안내 문구 (모든 라운드)

지금은 안내 창(`HudScene` toast)이 위쪽 가운데(`TOAST_TOP_Y`), 1라운드 가운데(`HUD_TOAST_LOW_Y` 660), 3·4라운드 아래(`HUD_TOAST_BOTTOM_Y` 1004)에 2.4초 뜬다. 이것을 바꾼다.

**플레이 중(물체가 움직이는 동안) 문구 → 상단 안내 줄**
- HUD 띠 안의 안내 줄(`createInstruction`, 지금 미션 지시문이 있는 자리)에 문구를 잠깐 바꿔 보여 준다. 시간이 지나면 원래 지시문으로 돌아간다.
- 눈에 띄도록 안내 줄 배경을 잠깐 반짝이거나 색 테두리를 준다. 오답(wrong)·주의(alert)·정보(info) 톤은 지금의 테두리 색 체계를 그대로 쓴다.
- 해당: 오답 문구(`wrongShotMessage`), 1라운드 연습 피드백과 명중 문구, 3·4라운드 "빔이 약해요"/"먼저 별을 맞혀 빔을 충전해요!", 미끼 별 안내, "장갑이 더 뜨거운 색으로 바뀌었어요!", "지금이 기회!".
- 오답 문구에 붙던 색 사다리(`toastLadder`)는 상단 스타게이지(같은 7색 순서)에서 **쏜 별의 색 칸을 잠깐 강조**하는 것으로 대신한다(제 판단: 같은 정보를 이미 있는 그림에서 보여 줌). 정답 범위 표시가 이미 있으면 그대로 둔다.
- "남은 목표" 숫자는 그대로 보인다. 문구가 길면 안내 줄 2줄 안에 들어가야 한다(7절 줄바꿈 규칙).

**게임이 멈추는 순간 → 화면 가운데 큰 안내 허용**
- 단계 전환(4절), 선체 온도 가득 → 미션 재시작 안내, 미션 끝(보스 격파/보스 도망 등 모든 물체가 멈춘 뒤)에는 가운데 큰 안내를 써도 된다. 이때는 위험한 물체가 움직이지 않아야 한다.

`TOAST_TOP_Y`·`'low'`·`'bottom'` 위치를 쓰는 플레이 중 호출은 남기지 않는다.

**1라운드 오답 사다리** (제 판단): 1라운드는 별 스타게이지가 아니라 쇳물 4단계(`FURNACE_STAGES`)를 쓴다. 상단에 쇳물 단계 표시가 있으면 그 칸을 강조하고, 없으면 안내 줄 오른쪽 안에 작은 4색 쇳물 사다리를 잠깐 그려 쏜 단계를 표시한다. 플레이 화면에는 그리지 않는다.

**안내 줄 문구가 겹칠 때** (제 판단): 새 문구가 이전 문구를 바로 바꾼다(최신 우선). 단, "장갑이 더 뜨거운 색으로 바뀌었어요!"와 단계·재시작 관련 문구는 최소 1.2초는 다른 문구에 덮이지 않는다. 시간이 지나면 **그 순간의 현재 지시문**(단계가 바뀌었으면 새 단계 지시문)으로 돌아간다.

**미션 끝 가운데 안내** (제 판단): "보스 함선을 격파했어요!"·"보스가 도망갔어요."처럼 미션 끝 안내를 가운데에 띄우기 전에, 남은 보스 탄·별·소행성을 판정·충돌 없이 정리(페이드)한다. 가운데 안내가 떠 있는 동안 움직이는 위험물은 없다.

## 4. 단계 전환 연출

**2라운드: 1단계(태양보다 뜨거운 별) → 2단계(태양보다 차가운 별)** — 교사 요청의 핵심.
1. 1단계 목표를 채우면 새 편대를 그만 내보낸다. 이미 화면에 있는 별·소행성은 판정·충돌 없이 사라진다(빠른 페이드 또는 화면 밖으로 빠짐 — 빌더 결정). 선체 온도는 오르지 않는다.
2. 화면 가운데 큰 안내: "1단계 완료!" → "이번엔 태양보다 **차가운** 별" (2~3초, 핵심 단어 강조).
3. 동시에 상단 스타게이지에서 정답 범위 표시(태양 화살표 기준 뜨거운 쪽 → 차가운 쪽)가 **움직여서 옮겨 가는 애니메이션**을 보여 준다.
4. 안내가 사라지고 상단 지시문이 2단계 문구로 바뀐 뒤 편대가 다시 내려온다. 이 시점부터 몸풀기처럼 첫 편대는 조금 여유 있게 들어와도 된다(빌더 결정).
- 전환 중 우주선은 움직일 수 있어도 되고 멈춰도 된다(빌더 결정). 발사는 무시한다.
- 일시정지·앱 전환·가로 회전 중에 전환이 진행되면 기존 일시정지 규칙을 따른다(멈췄다가 이어서).
- 같은 순간에 선체 온도가 가득 차면 **재시작이 이긴다**(제 판단): 단계 목표를 채운 프레임에 과열도 일어나면 지금처럼 미션을 처음부터 다시 하고, 전환 연출은 시작하지 않는다. 전환이 시작된 뒤에는 위험물이 없으므로 과열이 일어날 수 없다.

**1라운드: 연습 → 실전** (제 판단: 같은 방식으로 통일)
- 지금 가운데 뜨는 "이제 진짜예요! 흰색일 때만 쏘고, 부딪히면 선체 온도가 올라가요."를 같은 전환 연출(물체 정리 → 가운데 안내 2~3초 → 재개)로 바꾼다.

3·4라운드의 단계 변화(보스 장갑 단계)는 게임을 멈추지 않는다. 3절의 상단 안내 줄 + 5절 게이지로 알린다.

## 5. 3라운드: 드론 피해 누적

- 방어막보다 차가운 충전 = **튕김**, 피해 0 (지금과 같음, 교사 결정). 튕김의 오답 집계 규칙(`bounceCounts`)도 그대로.
- 방어막과 같거나 더 뜨거운 충전 = 뚫림. 피해 = **1 + (빔 충전 단계 − 방어막 단계)** (제 판단).
  - 예: 백색(5) 방어막, 드론 체력 3 → 백색 빔 3발, 청백색 빔 2발, 청색 빔 1발.
  - 예: 황백색(4) 방어막 → 황백색 3발, 백색 2발, 청백색·청색 1발.
  - 피해는 빔이 쏘아진 순간의 충전으로 정한다(I1 규칙 그대로). 크기·밝기 무관.
- 드론 체력 시작값 3 (`DRONE_HP`, `balance.js` 이름 있는 export). 방어막 없는 드론이 있다면 피해 1로 친다(제 판단).
- 드론마다 **작은 체력 막대**를 드론 아래쪽 또는 위쪽에 붙인다. 중립색 채움(흰색 계열), 맞을 때마다 줄어드는 게 보이게 짧은 애니메이션. 방어막 고리는 지금처럼 팔레트 색.
- 맞았지만 안 쓰러질 때: 짧은 피격 반짝임 + 피해 숫자(예: "-2")를 잠깐 띄운다(제 판단, 별 명중의 "+1" 글자와 같은 계열). 쓰러질 때는 지금의 폭발 연출.
- 드론을 맞히면 `director.onCorrect()`를 부르는 기존 규칙: 쓰러뜨렸을 때만 부를지, 뚫을 때마다 부를지는 빌더가 균형 모델과 함께 정한다.
- 균형: 드론 한 기에 여러 발이 필요해지므로 `M3_DRONE_GOAL`(쉬움 5/중간 6/어려움 8)과 시간 모델(`flow.js`, `difficulty.js`의 m3 몫)을 다시 맞춘다. 쉬움 ≤ 900초, 쉬움 dodge ≤ 0.4, 어려움 < 0.9 테스트 유지. 숫자 맞추기를 위해 학습과 무관한 값을 억지로 끼워 맞추지 않는다(이전 판정과 같은 원칙).
- 목표 수는 **쓰러뜨린 드론 수**로 센다(맞힌 횟수가 아님). 시간 목표를 맞추려면 `M3_DRONE_GOAL`(줄여도 됨, 최소 3)과 `DRONE_HP`(2~4)를 움직인다. 시간 모델 안의 플레이 추정값(드론당 걸리는 시간 등)은 "뚫는 데 필요한 발 수 × 한 발 쏘는 시간"처럼 규칙에서 유도하고, 테스트를 통과시키려고 근거 없이 바꾸지 않는다(제 판단).

## 6. 4라운드: 보스 체력 게이지

- **보스도 5절과 같은 피해 규칙**(교사 결정 2026-11-06 "응 알아서 조정해줘"): 장갑보다 차가운 충전은 튕김, 같거나 더 뜨거우면 피해 = 1 + (빔 충전 단계 − 장갑 단계). 단계마다 체력 `BOSS_HP`는 이 규칙에 맞게 다시 정한다(빌더). 210초 안에 쉬움·중간에서 깰 수 있고, 장갑 색 그대로의 빔만 쓰면 오래 걸리고 더 뜨거운 별을 쓰면 빨라지게. 시간 모델(`difficulty.js`의 m4 몫, `PACE`)도 규칙에서 유도해 맞춘다.
- **보스 체력 게이지**: 화면 위쪽, HUD 띠 바로 아래 또는 HUD 띠 안에 가로 막대(빌더가 보스 그림·탄 길과 겹치지 않는 위치를 정함; 날아오는 물체를 가리지 않아야 한다).
  - 채움: 현재 단계의 남은 체력 비율, 중립색(흰색 계열).
  - 테두리 또는 옆의 작은 칸: 현재 장갑 색(정확한 팔레트 hex) — "이 색 이상으로 충전" 정보.
  - 단계 표시: 점 3개 또는 "1/3단계" 글자.
  - 명중마다 줄어드는 애니메이션, 단계가 바뀌면 다시 가득 차는 연출.
- 보스가 나타날 때 보이고, 격파·도망 뒤 사라진다.

## 7. 줄바꿈 정리 (모든 화면)

- 대상: 게임에 나오는 모든 문구 — 타이틀, 브리핑, 상단 지시문, 상단 안내 줄(3절), 단계 전환 안내(4절), 정리 카드, 4라운드 질문·그래프, 귀환 보고서, 결과 화면, 일시정지·가로 회전 안내.
- 규칙: 한 단어(조사 포함 어절)는 중간에서 끊지 않는다. 의미 단위("방해 드론", "선체 온도", "태양보다 뜨거운 별")를 줄 사이로 가르지 않는다. 한 글자·한 어절만 다음 줄에 남는 줄(외톨이 줄)을 만들지 않는다.
- 방법: 어절 단위 줄바꿈을 기본으로 하고, 필요한 곳에는 문구에 직접 줄바꿈(`\n`)을 넣는다. 실제 표시 폭(720 px 게임 화면, 각 텍스트의 글꼴 크기)에서 확인한다.
- 산출물: 바꾼 문구의 전/후 목록(화면, 문구, 바꾼 줄)과 스크린샷 몇 장. 교사에게 보고.

## 8. 제약 (그대로 유지)

- 별은 파괴하지 않는다(측정 = 표시 고리 + 사라짐). 드론·보스는 격추 가능.
- 충전·피해·선체 온도는 색 7단계로만. 방어막·장갑·빔·HUD 충전 칸은 정확한 `STAR_COLORS` hex.
- 적 탄 규칙(속도 띠, `canLaunch` 안전 거리, 몸풀기 조준 없음, 쉬움 조준 없음), `M4_TIME_LIMIT_SEC` 210.
- 튜닝 수치는 `src/config/balance.js` 이름 있는 export. 순수 로직은 TDD. 매 작업 끝 `npm test`, `npm run build`.
- UI 글자는 이미지에 굽지 않는다. 새 버튼은 `armButton`.
- 커밋 끝: 빈 줄 + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## 9. 빌더에게 맡기는 것

안내 줄 반짝임 모양, 전환 중 물체가 사라지는 방식, 전환 안내 글꼴·길이(2~3초 안), 체력 막대·게이지 크기·위치·애니메이션, 피해 숫자 연출, m3 균형 수치, `director.onCorrect()` 호출 시점.

## 10. 제 판단으로 정한 것 (교사 확인용)

- 오답 색 사다리 → 상단 스타게이지 칸 강조로 대체.
- 1라운드 연습 → 실전도 2라운드와 같은 전환 연출.
- 드론 피해 = 1 + (충전 단계 − 방어막 단계), 드론 체력 3.
- 체력 막대·보스 게이지 채움은 중립색(팔레트 색과 헷갈리지 않게).
- 보스도 같은 피해 누적 규칙(교사 결정), 체력 수치는 빌더 조정.
