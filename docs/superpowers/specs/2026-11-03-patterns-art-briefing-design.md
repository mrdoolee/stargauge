# 별빛 탐사선 스타게이지호 — 플레이 패턴·난이도, 그림, 브리핑 설계

작성일: 2026-11-03
상태: 교사 검토 (2026-11-03)
상위 문서: `docs/superpowers/specs/2026-10-30-star-color-shooter-design.md` (이하 "본 스펙"). 이 문서가 본 스펙과 다르면 이 문서를 따른다. 승인되면 본 스펙의 해당 절(4-1, 5.1, 6, 7)에 개정 표시를 남긴다.

## 1. 의도와 배경

교사가 직접 플레이해 보니 세 가지가 아쉬웠다.

1. **같은 패턴만 반복된다.** 예: 미션 3에서는 함정 별이 늘 별자리 오른쪽 한 줄(`trapLane`)로만 떨어진다. 다른 미션도 "한 개씩 무작위 x에서 같은 속도로 떨어짐"뿐이다.
2. **너무 쉬워서 재미가 없다.** 교사 말: "분석한 게임처럼 게임이 어려움이 있어야 재밌지. 그냥 쉬우면 재미없어."
3. **그림이 별로다.** 지금은 전부 코드로 그린 임시 도형이다. 생성 이미지는 아직 하나도 없다.

또 교사는 미션에 들어가기 전에 **우주 선장이 핵심 이론을 짧게 브리핑하는 화면**을 원한다. 교사가 학생에게 해 줄 한마디의 예: "별은 온도에 따라서 색이 달라진다."

참고 자료는 `reference/games/s1945.zip`(Strikers 1945, Psikyo 1995 아케이드 ROM)을 Ghidra로 디컴파일해 얻은 난이도 구조다(2026-11-03 분석). 게임 방식(규칙·수치 구조)만 참고한다. 그림·소리·이름·문구는 가져오지 않는다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 미션마다 별이 편대·방향·속도를 바꿔 가며 나와서, 같은 판을 다시 해도 매번 조금씩 다르다.
- **쉬움**은 지금처럼 학생 누구나 끝까지 깬다. **중간·어려움**은 분석한 게임 수준의 손맛과 긴장감이 있다(교사 결정).
- 탐사선·선장·배경·소행성·별 모양이 승인된 그림체(아래 4.1)로 바뀐다.
- 미션 1~4 앞에 선장 브리핑 화면이 나온다.

**비목표**
- 배우는 내용(7색, 정답 판정, 실제 별 데이터, 미션 지시, 퀴즈) 변경.
- 학생 화면 밖 저장·전송, 로그인.
- 새 미션 추가.
- 효과음·배경음 새로 만들기 (이번 범위 아님).

**안티목표 (이러면 실패)**
- 별의 크기·밝기가 판정이나 선체 온도에 영향을 주는 것 (본 스펙 그대로).
- 생성 그림 때문에 별 7색이 교과서 색과 달라 보이거나 단계 구분이 흐려지는 것.
- 배경에 판정 대상으로 오해할 만한 점 별·반짝임이 있는 것.
- 위험물이 우주선 코앞에서 갑자기 튀어나와 "몰라서 틀린 것"과 "피할 수 없었던 것"이 구분되지 않는 것.
- 쉬움 난이도에서 학생이 끝까지 못 가는 것.
- 브리핑이 미션의 정답을 그대로 알려 줘서 미션이 시험 역할을 못 하는 것.
- 실제 별자리 안에 가짜 별을 넣는 것 (본 스펙 그대로).
- 별을 '파괴'하는 연출 (본 스펙 그대로: 표시·측정).

## 3. 1부 — 플레이 패턴과 난이도

### 3.1 분석한 게임에서 가져오는 규칙 (ROM에서 확인한 것)

| 분석한 게임 | 우리 게임에 적용 |
|---|---|
| 숨은 난이도 점수 = 메뉴 난이도×9 + 진행도×3 + 파워 + 생존시간 단계×3. 생존시간 단계는 30초까지 1, 이후 20초마다 +1(최대 9). | **긴장도(rank)** 값을 둔다. 미션 안에서 시간이 지날수록, 정답을 맞힐수록 오른다. |
| 죽으면 생존시간·파워가 0이 되어 점수가 떨어진다. | 선체 온도가 가득 차서 미션을 다시 하면 긴장도를 처음 값으로 되돌리고, 추가로 **한 단계 낮춰** 시작한다(같은 미션에서 최대 2단계 누적). |
| 점수로 탄 속도 단계(4단계, 단계당 +10~15%)를 고른다. | 긴장도로 위험물 속도 단계를 고른다(단계당 약 +12%). |
| 점수가 낮으면 플레이어와 가까운 적은 쏘지 않는다(초반 화면 높이 47%, 후반 9%). | **안전 거리**: 우주선과 세로 거리가 안전 거리보다 가까운 곳에서는 위험물을 새로 내보내거나 방향을 틀지 않는다. |
| 점수가 낮으면 플레이어 쪽(아래)으로만 쏘고, 옆·위로는 점수가 높아야 쏜다. | 조준(우주선 쪽으로 방향 틂)은 긴장도가 일정 이상일 때만, 그리고 위에서 아래 방향으로만. |
| 첫 30초는 점수가 낮아 기본 적이 거의 조준탄을 안 쏜다. | 미션마다 처음 10~15초는 **몸풀기**: 밀도 70%, 조준 없음. |
| 2회차는 탄 속도 ×1.25. | 참고값: 어려움의 속도 배율 기준. |

### 3.2 편대 패턴

위험물·목표 별은 하나씩 무작위로 떨어지지 않고 **편대**로 나온다. 편대는 순수 함수로 만들고(입력: 편대 종류·난이도·긴장도·난수, 출력: 각 개체의 등장 시각·위치·속도), 단위 테스트한다.

편대 종류 (빌더가 이름·세부를 정하되 최소 이만큼은 있어야 한다):
- **한 줄 비**: 가로로 3~5개가 시간차를 두고 떨어짐. 가운데 또는 한쪽에 빈틈이 있음.
- **V자 / 역V자**
- **대각선 쓸기**: 왼쪽 위에서 오른쪽 아래로(또는 반대로) 비스듬히 지나감.
- **양쪽 집게**: 좌우 끝에서 동시에 들어와 가운데로 모임. 가운데에 빠져나갈 길이 있음.
- **지그재그**: 좌우로 흔들리며 내려옴.
- **조준 한 발**: 위에서 내려오다 우주선 쪽으로 한 번 방향을 틂(긴장도 조건, 안전 거리 적용).

규칙:
- **반복 금지**: 같은 편대가 연달아 두 번 나오지 않는다. 출발 위치(왼쪽·가운데·오른쪽)도 직전과 겹치지 않게 돌린다.
- **피할 길 보장**: 어떤 순간에도 우주선이 지나갈 수 있는 가로 빈틈(우주선 폭의 1.5배 이상)이 있다. 테스트로 확인한다.
- **목표 별 보장**: 미션 2의 "필요한 색이 3번 연속 안 나오면 강제로 넣는" 규칙(`SPAWN_NEEDED_GUARANTEE`)은 편대 안의 한 자리를 바꾸는 방식으로 유지한다.
- 쉬움은 한 줄 비·V자·대각선만, 조준 없음.

### 3.3 미션별 적용

- **미션 1 (용광로)**: 30초 연습 구간은 그대로. 그 뒤 쇳물 덩어리가 편대로 떨어지고, 소행성은 조준 한 발로 섞여 나온다. 쇳물이 떨어지며 식는 규칙(흰→노→주→붉)은 그대로.
- **미션 2 (스타게이지)**: 7색 별이 편대로 나오되, 한 편대 안에 여러 색이 섞인다. 학생은 편대 안에서 쏠 별과 피할 별을 골라야 한다.
- **미션 3 (밝기의 함정)**: 별자리 묶음(오리온자리+시리우스)이 위에서 내려오면서 **좌우로 천천히 오간다**(지금은 세로로만 이동). 함정 별(이름 없는 크고 밝은 적색 별)은 **양옆 모두**에서 편대로 들어온다(대각선 쓸기, 양쪽 집게 등). 함정 별은 지금처럼 별자리 묶음의 경계 상자 안으로는 절대 들어가지 않는다(가짜 별이 별자리 안에 섞이지 않게). 이 경계 규칙은 테스트로 확인한다.
- **미션 4 (보석상자 성단 보스)**: 성단 별을 표시한 비율에 따라 **3단계**로 바뀐다.
  - 1단계 (0~33%): 청색 별이 한 개씩 흩어져 날아옴(지금과 비슷).
  - 2단계 (33~66%): 청색 별 2~3개가 부채꼴로 한꺼번에 퍼짐.
  - 3단계 (66~100%): 부채꼴 + 조준 한 발.
  - 단계마다 공격 뒤 **빈틈 구간**(약 2~3초, 흩어지는 별 없음)이 온다. 이때 표시하기 쉽다. 빈틈 시작을 화면 연출(성단이 잠깐 어두워지는 등)로 알린다.
  - 흩어지는 별은 안전 거리 규칙을 따른다. 우주선과 가까운 성단 별에서는 내보내지 않는다.
  - 보스(적색 초거성)는 지금처럼 공격하지 않고, 부딪혀도 선체 온도가 조금만 오른다.

### 3.4 난이도 수치 목표

단위는 "1초에 화면 높이(1280px)의 몇 배를 움직이나"(H/s). 분석한 게임의 탄은 가장 느린 것이 0.375 H/s, 중간 0.75 H/s, 최대 1.5 H/s였다.

| | 쉬움 | 중간 | 어려움 |
|---|---|---|---|
| 목표 별(판정 필요) 속도 | 지금 그대로 (0.10~0.15) | 0.25~0.35 | 0.35~0.45 |
| 피하기만 하는 위험물(소행성, 흩어지는 청색 별, 함정 별) 속도 | 지금 그대로 (0.09~0.18) | 0.375~0.55 | 0.5~0.75 |
| 안전 거리 (화면 높이 대비) | 45% | 30% | 20% |
| 가장 짧은 반응 시간 하한 (목표 별 / 위험물) | 2.0초 / 1.2초 | 1.0초 / 0.7초 | 0.8초 / 0.5초 |
| 편대 | 한 줄·V·대각선 | 전부 (조준은 긴장도 조건) | 전부, 조준 비율 높음 |
| 긴장도 상승 | 없음 (고정) | 있음 | 있음, 시작값 높음 |

- 반응 시간 = 위험물이 화면에 보이거나 출발한 순간부터 우주선 줄에 닿을 때까지 걸리는 가장 짧은 시간. **테스트로 확인하는 합격 기준**이다(지금의 `heatInflowPerSec`처럼 순수 함수로 계산).
- 위 값은 시작점이다. 수치 세부는 빌더가 정하되 위 하한·범위를 지킨다.
- 선체 온도 상승량(색 순서: 청색 최대 → 적색 최소)과 식는 속도는 바꿀 수 있지만, 색 순서는 그대로 둔다.
- **15분 문제 (교사 결정 2026-11-03)**: 쉬움은 15분 안에 끝나야 한다(본 스펙). 중간·어려움은 15분을 넘어도 된다. 실패할수록 쉬워지는 장치(3.1)로 끝없는 재시작을 막는다. `flow.js`의 예상 시간 표에 중간·어려움 추정치를 갱신한다.

## 4. 2부 — 그림

### 4.1 그림체 (교사 승인)

- **A안: 손으로 그린 아케이드풍.** 1945처럼 패널·리벳 디테일이 많고 묵직하지만, 고해상도로 깔끔하고 셀 셰이딩과 은은한 엔진 빛이 있다. 도트(픽셀) 그림, 흐릿한 저해상도, 2차 대전 비행기·군복 분위기는 뺀다.
- 기준 그림: `art/raw/ship-style-a.png` (2026-11-03 생성, 생성 스크립트 `art/raw/ship-style-a.prompt.mjs`). 나머지 에셋은 이 그림을 참조 이미지로 써서 같은 계열로 만든다.
- 기존 `art/art-direction-brief.md`를 A안 기준으로 갱신한다. 팔레트 역할(우주선 민트·은색, 별 7색은 다른 에셋의 주색으로 쓰지 않음)과 제외 항목(이미지 속 글자·숫자·로고, 배경의 점 별)은 그대로 유지한다.

| 선장 (상반신) | 표정 4가지: 기본, 웃음, 진지, 놀람 | 브리핑용. 친근한 베테랑 우주 선장, 밝은 카툰 성향이되 A안 그림체와 어울리게. 성별·외모는 빌더 판단, 교사 승인 |

| 빔·표시 효과, 조이스틱·발사 버튼 테두리 | 선택 | 빌더 판단 |

### 4.3 별 색 정확성 규칙

- 별 7색은 지금처럼 `src/config/palette.js` 값으로 코드가 입힌다. 생성 그림은 모양과 밝기만 맡는다.
- 화면에 그려진 별의 중심부 색이 팔레트 색과 같은지 자동으로 확인하는 테스트(또는 검사 스크립트)를 둔다.
- 별 그림을 바꾼 뒤에도 7단계가 서로 또렷이 구분되는지 교사가 실기기에서 확인한다.

### 4.4 도구

- **정지 그림**: OpenAI 이미지 API. 키는 `.env`의 `OPENAI_API_KEY`, 모델은 `OPENAI_IMAGE_MODEL`(교사 지정). 기존 `tools/gen-images.mjs`와 `art/asset-manifest.json`을 쓴다. 개발 시점에만 생성해 정적 파일로 저장하고, 키는 절대 커밋하거나 게임에 넣지 않는다.
- **움직이는 그림(스프라이트)**: <https://github.com/aldegad/sprite-gen> (교사 지정). 아틀라스 경로(`prepare → gen-set → extract → compose-atlas`)로 만들고, Phaser용 JSON으로 내보낸다(`export-aseprite`). 저장소 밖 `C:\Users\mrdoo\tools\sprite-gen`에 가상환경으로 설치한다. 아틀라스 경로는 ffmpeg가 필요 없다.
- **계정 (교사 결정 2026-11-03)**: sprite-gen의 움직이는 그림은 기본 경로인 Codex(ChatGPT 구독 로그인, 장당 요금 없음)로 만든다. 정지 그림은 OpenAI API 키로 만든다. Codex를 쓸 수 없어 sprite-gen이 다른 경로를 물으면(종료 코드 75) 빌더가 혼자 정하지 말고 교사에게 묻는다.
- 생성할 때마다 `art/PROVENANCE.md`에 모델·날짜·프롬프트 요약을 기록한다.
- 승인 순서: 선장 기준 그림 1장 → 교사 승인 → 표정·나머지 에셋.

### 4.5 성능

- 갤럭시탭 S6 Lite에서 60fps 목표, 30fps 이상 유지(본 스펙).
- 아틀라스 한 장은 2048×2048 이하. PNG 한 장 1MB 이하 목표. 화면 크기보다 훨씬 큰 원본은 줄여서 넣는다.
- 그림 교체 뒤 실기기에서 프레임 시간을 다시 재고 숫자로 보고한다.

## 5. 3부 — 브리핑 화면

### 5.1 화면 구성 (교사 승인: B안 + '가' 배치)

세로 화면 한 장. 위에서부터:
1. "MISSION N 브리핑" 작은 라벨, 미션 이름
2. **선장 상반신(왼쪽) + 말풍선(오른쪽)**: 핵심 이론 한 줄. 선장 말투는 학생을 "대원"이라 부르는 짧은 반말.
3. 그림 1장 (4.2의 브리핑 그림, 또는 코드로 그린 게이지)
4. 짧은 설명 3줄 (글머리표)
5. 임무 한 줄 (노란 테두리 상자)
6. "출발!" 버튼 (`armButton`: 화면이 뜬 뒤 300ms 이상 지난 누름만 인정)

- 읽는 데 20~30초. 글자는 이미지에 굽지 않고 코드로 쓴다. 휴대폰에서도 읽히는 크기.
- 선장 그림이 없으면 코드로 그린 실루엣으로 대신한다(게임이 멈추지 않게).
- 흐름: 난이도 선택 → 브리핑 1 → 미션 1 → 정리 카드 → 브리핑 2 → 미션 2 … → 브리핑 4 → 미션 4 → 귀환 보고서. 정리 카드(미션 뒤)는 그대로 둔다.
- 선체 온도가 가득 차서 미션을 다시 할 때는 브리핑을 다시 보여 주지 않는다.

### 5.2 미션별 문구 초안 (교사 검토 필요)

정답을 그대로 알려 주지 않고, 판단 기준(색으로 온도를 비교한다)만 알려 준다.

**미션 1 · 용광로 탈출** (선장 표정: 기본)
- 말풍선: "대원, 쇳물은 뜨거울수록 흰색, 식을수록 붉은색이야."
- 그림: 용광로에서 쇳물이 흘러나오며 색이 변하는 모습
- 설명: • 쇳물은 식으면서 흰색 → 노란색 → 주황색 → 붉은색으로 변해요. • 빛의 색을 보면 온도를 짐작할 수 있어요. • 별도 같은 원리로 색을 띠어요.
- 임무: 가장 뜨거운 쇳물을 쏘세요.

**미션 2 · 스타게이지 보정** (표정: 진지)
- 말풍선: "별은 온도에 따라 색이 달라."
- 그림: 7칸 색 게이지 (코드로 그림, 교과서 그림 8-5 순서)
- 설명: • 청색일수록 표면 온도가 높아요. • 적색일수록 표면 온도가 낮아요. • 태양은 황색 별이에요. 태양을 기준으로 비교해요.
- 임무: 태양보다 뜨거운 별만 쏘고, 나머지는 피하세요.

**미션 3 · 밝기의 함정** (표정: 놀람)
- 말풍선: "크고 밝다고 뜨거운 게 아니야. 색을 봐!"
- 그림: 이름 없는 크고 붉은 별과 작고 푸른 별 (실제 별 아님)
- 설명: • 별의 크기와 밝기는 표면 온도와 관계없어요. • 표면 온도는 색으로 비교해요. • 오리온자리와 큰개자리의 별을 살펴봐요.
- 임무: 세 별 중 가장 뜨거운 별을 찾아 쏘세요.

**미션 4 · 보석상자 성단** (표정: 웃음)
- 말풍선: "마지막 임무야. 성단의 별을 모두 측정해!"
- 그림: 추상화한 성단 (실제 사진 아님)
- 설명: • 성단은 별이 모여 있는 무리예요. • 별마다 색을 보고 표면 온도를 비교해요. • 실제 성단을 바탕으로 단순화했어요.
- 임무: 시간 안에 성단의 별을 모두 표시하세요. 흩어지는 청색 별은 피하세요.
- NOIRLab 자료를 화면에 쓰면 크레디트를 보이는 곳에 표기 (본 스펙).

## 6. 제약

- Phaser 4.2 + Vite, 세로 720×1280, `scale: FIT`, 터치 기준 (본 스펙 8절의 스킬 규칙 그대로).
- 미션 재시작 시 상태는 `init()`에서 초기화. 별·위험물은 오브젝트 풀 사용.
- 편대·긴장도·안전 거리·반응 시간 계산은 Phaser 없이 돌아가는 순수 함수로 두고 `tests/`에 단위 테스트를 둔다.
- `.env`(API 키)는 커밋 금지. 원본 생성 그림은 `art/raw/`(git 제외), 정리된 그림만 `public/img/`.
- GitHub·Vercel 배포는 보류 중 (로컬 개발 먼저).
